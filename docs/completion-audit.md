## Remaining work and interpretation limits

No additional missing retained workflow was confirmed in this bounded final pass after the incomplete-record and historical-payment paths were added. That statement is not a proof of every supported-input combination. The final integration pass verified the newest financial-history, service and payment-term controls through their actual browser and server workflows. A failing acceptance journey is a defect to resolve, not a reason to mark its requirement complete because a registry entry exists.

Historical debt aging cannot be reconstructed from today's cumulative paid amount. The application explicitly labels current aging/concentration as current. Historical collections/payments require the new actual dated observations. Missing dates, partial records, incompatible currencies/units and unsupported model combinations remain excluded or rejected with an explanation; they never receive a fabricated value.

The ordinary Workspace remains extensible JSON with shared structural checks and feature-specific validation. SQLite, the local worker, guest/account credentials and role enforcement are functional local implementations, not a completed production data platform. Retention is indefinite with reversible archive. Current-record export and a tested consistent SQLite backup CLI are available. No real legacy workspace was assigned to an account without an exact authorized mapping; the local ownership CLI remains the recovery path.

## Explicitly outside the retained product scope

The 3D renderer, live provider/bank/POS/ERP integrations, external transaction execution, automated messages or business actions, live LLM integration, production model optimization, calibrated uncertainty, advanced allocation/routing, manufacturing/perishability and production security/availability commitments remain outside the PRD boundary. Focused runs provide bounded scene manifests; exploratory results need no renderer. No production deployment has been performed.

Operational decisions and commands are in `samby-backend/README-prototype.md`, `implementation/platform-contract.md` and `implementation/analytical-contract-v2.md`. The current integrated service runs on `127.0.0.1:8001`; health reports SQLite persistence and an active worker.

Packaging is aligned with the current default app: `pyproject.toml` identifies Samby v0.4 and declares the exact installed/verified runtime pins, with test and legacy-template extras separated. Default pytest selection exercises the current application. The Dockerfile includes the Linux OpenMP runtime needed by LightGBM; a container build/deployment has not been verified or claimed.
